# AI 作文批改助手

面向一线语文教师和学校教研团队的作文批改工作台。教师上传学生作文照片后，AI 会生成逐段建议、修改稿、诊断、等级和家长反馈；所有结果都可以由教师复核、修改，再导出为 PDF 或 Word。

> AI 负责完成耗时的初步分析，教师负责最终判断。这个项目不是自动判分器，也不能替代教师对学生真实情况的了解。

## 这个项目可以帮助你做什么

| 教师工作 | 系统提供的帮助 |
| --- | --- |
| 准备作文题目 | 根据题目、年级和目标字数生成写作要求、结构要求与评分侧重，也可以保存常用题目 |
| 阅读纸质作文 | 接收 1 至 4 张作文照片，支持调整页序、旋转和裁剪后再提交 |
| 完成初步批改 | 按自然段识别作文内容，生成逐段修改建议、修改稿、主题判断和等级建议 |
| 找出主要问题 | 从真实度与切题、素材与细节、结构、语言流畅度 4 个维度给出诊断和修改动作 |
| 帮学生修改 | 每段保留原文裁图，给出具体问题、修改动作和示例，并生成可继续编辑的修改稿 |
| 与家长沟通 | 生成亲切详细、专业清晰、简短微信版 3 种反馈，教师可修改并一键复制 |
| 整理与交付结果 | 保存批改历史，单篇和批量均支持 PDF 与 Word，多份报告会按格式打包下载 |

## 适合哪些场景

- 语文教师希望先由 AI 逐篇完成日常作文初批，再集中进行人工复核。
- 学校希望统一作文评价维度，沉淀更清晰的批改流程。
- 教师需要把“问题在哪里、学生下一步怎么改”写得更具体。
- 教师需要快速整理一份可打印、可分享给学生或家长的批改报告。

它不适合在无人复核的情况下直接给学生定级，也不建议用于中考、高考等高风险正式评分场景。

## 一次批改是怎样完成的

1. **设置题目：** 选择内置题目或填写自定义题目，明确年级、字数、结构要求和评分重点。
2. **整理图片：** 拍照或选择 1 至 4 张 JPG、PNG、WebP 图片，调整页序、旋转方向和裁剪范围。单张图片不能超过 20 MB。
3. **发起分析：** 确认隐私提示后提交作文；视觉模型先按自然段识别文字，内容模型再根据识别文字生成批改。新分析会写入 OCR v2。
4. **教师审核：** 先检查「识别原文」，再对照原文裁图核对每段建议、修改稿、生活常识、前后逻辑和等级，并完成明确的人工审核确认。
5. **导出结果：** 只有经过教师审核的作文才能导出；教师可以在待导出清单中再次核对修改意见，再单篇或批量下载 PDF 或 Word。

如果图片模糊、缺页或无法辨认，系统会提示重新拍摄，不会把不完整的识别结果包装成正式报告。

视觉模型只负责 OCR，包括逐页转写、自然段合并和文字块定位，不负责评分、诊断或改写。内容模型只接收识别文字；更具体地说，内容模型只接收自然段文字，不接收作文图片、图片地址、定位坐标或 OCR 内部文字块。系统使用视觉模型返回的定位结果确定性地裁出每段原文。

教师可以在「识别原文」中逐段修正错字或漏字。保存后，旧报告仍然可见，但会提示「批改报告基于旧版识别原文」；点击「重新生成批改」只调用内容模型。只有新报告生成并保存成功后，旧报告才会被替换。

早期记录采用逐页 OCR 和示范段落报告，不能伪转换为逐段交付。旧报告需要完整重新分析才能生成新格式；如果同一 revision 已存在的旧版 PDF 可原样下载，页面会提供独立下载入口。没有对应缓存时，只显示完整重新分析入口。

PDF 和 DOCX 都按「原文裁图 → 修改建议 → 修改后段落」的顺序生成 A4 纵向文档。DOCX 中的建议和修改稿可以继续编辑，但下载后不会自动重算红黑差异；教师改动 Word 内容时，需要自行同步调整颜色和删除线。导出会先完成全部文件生成再开始下载，导出失败不会标记为已导出。

## AI 会生成哪些内容

- 审题判断：切合题意、部分切题或偏离题意，并给出判断依据。
- 优点与待修改项：使用学生容易理解的短句概括关键问题。
- 等级建议：从 A+ 到 C 的 7 档等级，教师可以重新选择。
- 四维诊断：分别说明问题的具体位置，以及学生可以执行的修改动作。
- 逐段建议：每个自然段提供 1 至 4 条具体建议，包含问题、修改动作和示例；表达成熟的段落会说明保留理由。
- 修改稿：逐段生成可编辑文本，文字增删换用红色标记，删除内容带删除线；调序和纯标点变化保持黑色。
- 家长反馈：提供 3 种沟通风格，方便教师根据沟通场景选择。

## 教师需要重点复核什么

AI 可能误读字迹、遗漏上下文，或者给出不符合班级教学要求的建议。导出报告前，建议至少检查：

- 学生原文是否按自然段识别准确，跨页段落的裁图是否连续完整。
- 时间、地点、人物身份、物品状态和因果关系是否符合生活常识，前后文是否紧密连贯。
- 主题判断、等级和修改建议是否符合本次教学目标。
- 逐段建议和修改稿是否适合学生当前年级，是否保留了学生自己的表达空间。
- 家长反馈中是否包含未经证实的推断或不合适的语气。
- 学生姓名、学校、班级、学号等无关身份信息是否已从图片中遮盖。

## 使用前需要知道

- 当前版本面向受邀教师内测，不提供公开注册。学校或教研组需要先完成部署，再由管理员创建账号。
- 管理员需要分别配置支持图片理解的视觉模型和适合作文生成的内容模型；两者可以来自不同的 OpenAI 兼容服务。
- 作文图片只会发送给视觉模型；OCR 文字会发送给内容模型。第三方如何保存和处理数据，以其服务条款为准。
- 云端版本使用 Cloudflare D1 保存业务数据、Cloudflare R2 保存作文图片，并通过账号隔离不同教师的数据。
- 已上传的作文图片、识别原文和批改报告会长期保留，不再设置 30 天自动到期。教师可以在历史记录中手动永久删除；超过 24 小时仍未上传图片的空草稿会自动清理。
- 长期保留会持续占用存储容量。部署方需要监控 Cloudflare D1、Cloudflare R2 和本机磁盘用量，并根据学校的数据管理要求制定容量告警与加密备份策略。
- API Key 会加密保存或通过 Cloudflare Secret 配置，前端页面不会读取或回显完整密钥。

## 当前技术架构

```text
教师浏览器
  ├─ 拍照、图片整理、批注编辑、PDF 生成
  └─ Next.js 静态前端
          │
          ▼
Cloudflare Worker API
  ├─ D1：账号、题目、批改报告、任务状态
  ├─ R2：作文图片与相关文件
  ├─ Queues：异步 AI 批改任务
  ├─ OpenAI 兼容视觉模型：OCR 与文字块定位
  └─ OpenAI 兼容内容模型：纯文本报告与批注锚点生成
```

主要技术栈为 Next.js 16、React 19、TypeScript、Cloudflare Workers、D1、R2、Queues、Vitest 和 Playwright。

## 开发与部署

### 环境要求

- Node.js >= 24
- npm
- Cloudflare 账号与 Wrangler 登录状态（运行完整云端服务时需要）
- 支持图片理解的 OpenAI 兼容视觉模型 API
- 适合作文内容生成的 OpenAI 兼容内容模型 API

### 安装与本地 Cloudflare 调试

```bash
npm install
cp .dev.vars.example .dev.vars
npx wrangler d1 migrations apply ai-composition-grader --local
npm run build
npm run cf:dev
```

请先在 `.dev.vars` 中填写本地开发所需的密钥。完整登录和批改流程还需要准备测试账号、D1 数据及 R2、Queue 等绑定；不要把真实密钥、学生作文或数据库导出提交到 Git。

推荐分别设置 `VISION_AI_API_KEY` 和 `CONTENT_AI_API_KEY`。视觉角色和内容角色的服务地址、模型名称及加密密钥也可以在设置页独立保存。旧部署可暂时保留 `AI_API_KEY`，它会在角色密钥缺失时作为兼容回退；迁移完成后应删除这个共享密钥。

### 常用命令

```bash
# 单元与组件测试
npm test

# 代码检查
npm run lint

# 生产构建
npm run build

# Playwright 端到端测试
npm run test:e2e

# 部署 Cloudflare Worker
npm run cf:deploy
```

Cloudflare 资源绑定和部署入口定义在 `wrangler.jsonc`，数据库迁移位于 `migrations/`。首次部署前需要创建或替换为自己的 D1、R2 和 Queue 资源，并安全配置生产 Secrets。

仓库仍保留早期 macOS 本机内测版的 SQLite、Keychain、后台 Worker 和 ngrok 代码。相关说明见 [旧版内测操作手册](docs/private-beta-runbook.md)，不代表当前云端版本的数据保存方式。

## 项目结构

- `app/`：教师工作台页面、组件和浏览器端 PDF 生成逻辑。
- `src/ai/`：作文分析、题目要求生成和内容重写适配器。
- `src/cloudflare/`：D1、R2、登录和云端 AI 请求实现。
- `src/domain/`：题目、批注、报告和任务状态的数据契约。
- `worker/`：Cloudflare Worker API 与 Queue 消费入口。
- `migrations/`：Cloudflare D1 数据库迁移。
- `e2e/`：Playwright 端到端测试。
- `docs/`：设计记录、实施计划和旧版内测说明。
