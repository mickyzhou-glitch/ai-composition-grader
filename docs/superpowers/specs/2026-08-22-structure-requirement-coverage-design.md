# 作文结构要求逐项分析设计

## 背景

教师可以在新建批改时填写结构要求，但当前云端分析链路只把整份
`AssignmentConfig` 作为 JSON 传给内容模型。模型没有被要求逐项核对编号要求，
服务端也只校验 `diagnostics.structure.finding` 和 `action` 非空，因此五项要求可能被
压缩成一句笼统判断并直接保存。

旧图片直读链路已有「按 `structureRequirements` 逐段核对」的提示规则，但当前
Cloudflare Worker 使用 OCR 后的纯文本分析链路，这条规则没有完整迁移。

## 目标

- 识别教师在 `structureRequirements` 中填写的连续编号要求。
- 要求内容模型逐项给出符合情况和原文依据，不能用一句总评代替。
- 在服务端确定性检查逐项结果是否完整；缺项时触发现有单次自动修复。
- 保持现有报告结构、历史数据、复核编辑页和 PDF 导出兼容。
- 让旧图片直读链路和 OCR 纯文本链路复用同一套结构分析规则。

## 非目标

- 不新增 `structureChecks` 数据库字段或公共 API 字段。
- 不修改教师填写结构要求的界面。
- 不使用关键词相似度判断模型结论是否正确；服务端只负责覆盖完整性，具体教学判断
  仍由模型依据原文完成。
- 不把普通自然语言中的逗号、分号或「首先、然后」猜测为多个独立要求。

## 编号要求解析

新增纯函数解析 `structureRequirements`。只有文本包含至少 2 个连续的阿拉伯数字编号，
并从 `1` 开始时，才启用逐项模式。支持 `1.`、`1、`、`1．`、`1)`、`1）` 等常见
写法，编号可以位于同一行或多行。

解析结果保留每项去除首尾空白后的原文，不改写教师要求。编号不连续、重复、缺少正文
或只有 1 项时，整体按单项自然语言要求处理，避免错误拆分。

例如截图中的文本会解析为 5 项：

1. 倒叙或插叙开头并描写紧张心情。
2. 说明事情的重要性和面对的困难。
3. 描述如何克服困难并详写努力过程。
4. 介绍事件结果。
5. 升华主题并回扣标题。

## 模型输出约定

逐项模式下，两个分析适配器都向模型提供拆分后的编号清单，并要求先核对原文，再输出
结构诊断：

- `diagnostics.structure.finding` 必须按顺序包含恰好对应数量的行。
- 每行以稳定标记 `【第 N 项】` 开头，写明「符合」「部分符合」或「不符合」，并引用或
  定位原文证据。
- `diagnostics.structure.action` 只针对部分符合或不符合的项目给出可执行修改；全部符合时
  明确说明无需结构调整。
- 结构类 `annotationAnchors` 继续定位到可辨认的原文句子或段落起点，可以返回多条。
- 等级判断必须以逐项核对结果为依据，不能先定等级再补结构说明。

非逐项模式仍输出现有的一组结构判断和修改动作，不强制使用标记。

## 服务端校验与自动修复

报告语义校验根据同一解析结果检查 `diagnostics.structure.finding`：

- 逐项模式必须且只能出现 `【第 1 项】` 到 `【第 N 项】`，顺序一致且每项只出现一次。
- 标记缺失、重复、越界或乱序时抛出稳定的 `structure_coverage` 校验错误。
- 内容模型第一次返回不完整时，复用现有单次修复请求；修复提示包含原文、无效响应、
  完整编号清单和 `structure_coverage` 原因。
- 修复后仍不完整时返回现有 `AI_INVALID_RESPONSE`，不保存不完整报告。

校验不尝试判断「符合」结论是否教学上正确，也不要求 `action` 重复全部标记，以免为了
机器校验制造冗余文案。

## 数据流

1. 新建批改页提交完整 `AssignmentConfig`。
2. Worker 从作文记录读取当前配置并传给 `CompositionReviewAdapter`。
3. 共享解析器拆分编号要求，构建逐项分析规则。
4. 模型依据 OCR 原文生成报告和原文锚点。
5. 共享语义校验器检查报告结构及逐项覆盖。
6. 覆盖不完整时自动修复一次；通过后才保存报告。

旧图片直读适配器在构建初次请求、继续请求和修复请求时调用同一规则，并在保存前调用
同一语义校验，避免两条部署路径再次分叉。

## 展示与兼容性

逐项结论以换行文本保存在现有 `diagnostics.structure.finding` 中，现有 `<textarea>`、
批量审核页和 PDF 文本展示均可直接呈现，不需要 Schema 或数据库迁移。

复核页不再把结构维度硬编码为「五段结构」，统一显示「结构要求」，以适配书信、说明文
以及非 5 段作文。历史报告仍按原样读取和编辑，不追溯校验旧数据。

## 测试策略

- 纯函数测试覆盖同一行、多行、常见标点、连续编号、编号缺失和普通自然语言。
- 内容适配器测试先证明旧提示词没有逐项规则，再验证新提示词包含完整清单和输出约定。
- 语义测试覆盖完整、缺项、重复、乱序和越界标记。
- 自动修复测试确认第一次缺项会携带 `structure_coverage` 重试，第二次完整后成功。
- 旧图片直读适配器测试确认初次、继续和修复提示均使用共享规则。
- 页面测试确认结构维度显示「结构要求」，不再硬编码「五段结构」。
- 回归测试确认普通自然语言结构要求和历史报告不受影响。

## 成功标准

对于包含 5 个连续编号结构要求的作文，任何新保存的 AI 报告都必须在结构诊断中按顺序
出现 `【第 1 项】` 至 `【第 5 项】`，每项包含符合情况和原文依据；缺少任意一项的模型
响应不得直接保存。
