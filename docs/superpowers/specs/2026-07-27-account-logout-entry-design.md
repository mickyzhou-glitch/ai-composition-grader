# 登录后退出账号入口设计

## 背景

当前应用已具备登录页和 `POST /api/auth/logout` 接口，但登录后的页面没有可见的退出入口。用户只能依赖会话过期或手动清理浏览器数据，无法主动切换到另一个账号。

## 目标

在所有登录后页面的顶部导航中提供一个清晰、稳定的“退出登录”按钮。退出成功后清除当前会话并返回登录页，用户可立即使用其他账号登录。

## 范围

- 在现有 `AppHeader` 的主要操作区增加“退出登录”按钮。
- 所有使用 `AppHeader` 的登录后页面自动获得该入口。
- 点击按钮后调用现有 `POST /api/auth/logout` 接口。
- 请求进行中显示“正在退出…”并禁用按钮，防止重复提交。
- 退出成功后使用 App Router 将页面替换为 `/login`，并刷新路由缓存。
- 退出失败时保留当前页面和会话，向用户显示可理解的错误提示。

## 非目标

- 不新增账号管理页面。
- 不新增账号选择器、下拉菜单或账号列表。
- 不修改登录、密码修改、账号创建与权限逻辑。
- 不改变现有退出 API 的安全校验和 Cookie 处理。

## 组件与数据流

`AppHeader` 已是客户端组件，负责全局顶部导航。退出交互直接封装在该组件中：

1. 用户点击“退出登录”。
2. 组件将按钮切换为忙碌状态。
3. 组件通过现有 API 客户端请求 `POST /api/auth/logout`。
4. 成功时执行 `router.replace("/login")`，随后执行 `router.refresh()`，避免保留受保护页面缓存。
5. 失败时恢复按钮，并在导航区域显示错误信息。

服务端继续由现有退出路由撤销当前 Session 并清除对应 Cookie，不引入新的后端接口。

## 界面

按钮位于顶部导航右侧，与“新建作文批改”和管理员“设置”保持同一视觉层级，使用现有安静按钮样式。按钮文案为“退出登录”；请求期间为“正在退出…”。

错误提示采用紧凑的状态文本，并通过无障碍状态区域向辅助技术播报，不遮挡主要页面内容。

## 测试

- `AppHeader` 显示“退出登录”按钮。
- 点击后以 `POST` 请求退出接口。
- 请求期间按钮禁用并显示忙碌文案。
- 成功后替换到登录页并刷新路由。
- 失败后恢复按钮并显示错误提示。
- 管理员与教师角色均显示退出入口，现有“设置”权限显示规则保持不变。

## 成功标准

任意已登录账号都能从所有主要受保护页面顶部主动退出，并立即回到登录页；退出失败不会误导用户认为会话已经结束。
