# AI 作业批改助手 Cloudflare 免费云端版设计

## 目标

将当前依赖本机持续开机的 AI 作业批改助手迁移为完全运行在 Cloudflare 免费额度内的云端应用，同时保留全部现有用户功能、现有三位教师的数据归属和原有账号密码登录体验。

生产环境不依赖用户电脑。代码由 GitHub 管理，`main` 分支自动发布到免费的 `*.workers.dev` 地址。Cloudflare 托管不得自动进入付费额度；达到免费额度安全线时，系统应降级或暂停相关写入功能。

AI 模型调用费用不属于 Cloudflare 托管费用。所有教师共用一个由管理员配置的 AI 服务地址、模型和 API Key。

## 已确认的范围

- 首个云端版本保留全部现有功能，包括登录、修改密码、作业上传、AI 批改、任务进度、历史记录、报告编辑、图片标注、HEIC 处理、示范段落生成、单份 PDF、批量 PDF、数据删除和安全审计。
- 迁移现有三位教师账号，不开放公开注册。
- 保持原有账号密码登录方式及现有密码。
- 使用免费的 Cloudflare 域名，不要求购买自定义域名。
- 全量迁移现有数据库和用户文件。
- 迁移完成后保留一份本地只读备份，停止本机生产服务。
- 不启用自动付费。免费额度耗尽时暂停相关功能，并在额度恢复后自动恢复服务。

## 总体架构

应用采用“静态前端 + 轻量 Cloudflare API”的架构。

- 静态 React 前端由 Cloudflare Workers Static Assets 托管。静态资源请求不执行应用 Worker 逻辑。
- API Worker 负责身份验证、授权、业务数据读写、R2 上传授权、AI 请求协调和任务状态查询。
- Cloudflare D1 保存用户、登录挑战、会话、作业、批注、报告、任务状态、系统设置和安全审计。
- Cloudflare R2 保存原始作业图片、标准化图片、标注图片和生成的 PDF。
- Cloudflare Queues 承载异步 AI 批改任务，并配置有限重试和死信队列。
- 浏览器执行图片解码、方向纠正、压缩、标注合成、PDF 排版和批量打包等高 CPU 操作。
- Workers Secrets 保存共享 AI Key、登录验证材料加密主密钥及其他生产密钥。
- Cloudflare Workers Builds 连接 GitHub。Pull Request 生成预览版本，`main` 分支自动发布生产版本。

页面和 API 共享同一个 `*.workers.dev` 域名，避免跨域 Cookie、CORS 和多域名配置。

## 前端职责

前端继续提供现有教师工作台的交互和视觉体验，并承担免费 Worker 不适合执行的重计算。

### 图片处理

- 支持 JPG、PNG、WebP 和 HEIC。
- 在浏览器内完成格式识别、HEIC 解码、EXIF 方向纠正、尺寸约束和质量压缩。
- 保留现有画布标注编辑器。
- 在浏览器合成标注结果并计算 SHA-256。
- 通过短时上传授权将原图、标准化图片和标注结果直接写入私有 R2。
- 上传完成后由 API Worker 校验对象元数据，再创建正式数据库记录。

### PDF

- 在浏览器端按现有三栏版式生成单份 PDF。
- PDF 必须包含现有打印页面中的评分、批注图、报告内容和示范段落。
- 批量导出在浏览器逐份生成 PDF，并打包为一个下载文件。
- 生成结果可选择上传至 R2，供后续直接下载。
- 生成失败不得覆盖已存在的 PDF 或业务数据。

### 任务体验

- 创建 AI 批改任务后轮询任务状态。
- 明确区分排队、处理中、完成、可重试失败、免费额度耗尽和 AI 额度耗尽。
- 浏览器刷新后能够从 D1 中恢复任务状态。

## API Worker 职责

API Worker 只执行适合免费 CPU 限制的轻量操作：

- 验证登录挑战、会话和用户身份。
- 验证所有资源的用户归属。
- 执行参数校验、轻量数据转换和 D1 查询。
- 签发短时、最小权限的 R2 上传或下载授权。
- 创建 Queue 消息和查询任务状态。
- 使用共享 AI Secret 调用管理员配置的 AI 服务。
- 记录不含敏感内容的安全事件。
- 执行免费额度安全线检查。

Worker 不执行 Sharp 图片变换、本机文件操作、本机 Chromium 或服务端 Argon2。

## 数据库设计

### D1 数据

现有 SQLite 业务模型迁移到 D1，并保留现有租户隔离语义：

- 用户和云端密码验证材料
- 登录挑战、会话、失败次数和账号锁定
- 作业、作业配置和保存的作业模板
- 图片元数据、批注和报告
- AI 分析任务、进度、租约、重试和失败原因
- AI 服务地址和模型名称
- 安全事件和数据保留状态

现有同步 `better-sqlite3` Repository 替换为异步 D1 Repository。领域服务依赖明确的异步 Repository 接口，不直接依赖 Cloudflare Binding。

共享 AI API Key 不写入 D1。D1 仅保存非密钥的 AI 服务地址和模型名称。

### R2 对象

R2 Bucket 默认私有。对象键使用以下稳定结构：

```text
users/{userId}/reviews/{reviewId}/{kind}/{filename}
```

其中 `kind` 为受控枚举，例如 `originals`、`normalized`、`annotations` 或 `pdf`。D1 保存对象键、内容类型、字节数、SHA-256、创建时间和业务归属。

任何下载都必须先通过业务授权。任何上传授权都必须限制对象键、内容类型、最大字节数和短有效期。

### 删除一致性

删除作业采用可恢复状态机：

1. 在 D1 中标记 `deleting`。
2. 删除该作业关联的 R2 对象。
3. 确认对象清理结果。
4. 删除或匿名化关联业务记录。
5. 写入不包含作业内容的审计事件。

R2 清理失败时保留 `deleting` 状态并进入有限重试，不允许直接丢弃数据库归属信息。

## 原账号密码登录

生产环境保留账号和密码输入方式，但将高 CPU 的 Argon2 计算移至浏览器。

### 登录协议

1. 浏览器提交账号，请求一次性登录挑战。
2. Worker 返回该账号的公开盐值、一次性随机数和挑战有效期；不存在的账号返回不可区分的伪挑战。
3. 浏览器使用 Argon2id 和密码计算验证材料。
4. 浏览器以验证材料和一次性随机数计算登录证明。
5. Worker 解密 D1 中保存的账号验证材料，恒定时间验证登录证明，并原子消费挑战。
6. 验证成功后创建带 `HttpOnly`、`Secure`、严格 `SameSite` 属性的会话 Cookie。

一次性挑战必须短期有效、只可使用一次，并绑定账号和登录流程。错误账号和错误密码返回相同的外部错误信息。

### 密码迁移

现有 Argon2 服务端哈希不能直接转换为浏览器验证材料。迁移工具在本机终端为每位教师交互式读取一次现有密码：

- 输入不回显。
- 先使用现有本地 Argon2 哈希验证密码正确。
- 生成新的公开盐和浏览器端验证材料。
- 使用迁移环境中的生产加密公参生成可导入数据。
- 不将密码写入磁盘、日志、命令历史或 GitHub。

教师继续使用原账号和原密码。修改密码时在浏览器生成新的验证材料，并通过已认证会话提交更新。

### 登录防护

- 保留登录失败计数、临时锁定、安全事件和会话撤销。
- 挑战、防重放和账号锁定必须由 D1 原子写入保证。
- 登录验证材料使用 Workers Secret 中的主密钥加密。
- 任何日志不得包含密码、验证材料、登录证明、完整会话令牌或密钥。

## AI 批改与后台任务

所有教师共享一个管理员配置的 AI Key。

- AI 服务地址和模型名称保存在 D1。
- API Key 仅存为 Workers Secret。
- 教师可以查看非敏感配置和执行连接测试，但不能读取或修改 API Key。
- 管理员通过 Cloudflare Secret 管理流程更新 API Key。

任务创建后写入 D1 并发送 Queue 消息。Queue Consumer 负责调用外部 AI 服务、校验结构化响应并写回任务进度及报告。

Queue 配置有限重试和死信队列。业务操作必须幂等：重复消息不得创建重复报告、重复文件或重复扣减应用内任务额度。

管理员可配置每日 AI 任务上限。达到上限后停止创建新任务，但允许查看和导出已有结果。

## 免费额度保护

系统不得启用 Workers Paid，也不得自动购买容量。

应用设置低于官方免费额度的内部安全线：

- R2 业务对象总量上限为 8 GB。
- D1 数据总量上限为 4 GB。
- 每个文件和每次上传继续执行现有大小限制。
- 管理员配置每日 AI 任务上限。

达到 R2 或 D1 安全线后：

- 停止创建新作业和上传新文件。
- 允许登录、查看、编辑不增加大量存储的数据及导出现有内容。
- 显示明确的中文额度提示。
- 不自动升级服务计划。

Workers、D1 或 Queue 的平台级免费额度耗尽时，应用显示可恢复的额度错误；额度重置后无需数据迁移即可恢复。

## 安全边界

- 所有 API 重新验证身份，不能信任浏览器提交的用户 ID。
- 所有 D1 查询和 R2 对象操作验证资源归属。
- Bucket 不允许公开列举或公开读取。
- 共享 AI Key、登录加密主密钥和迁移密钥使用 Workers Secrets。
- 保留内容安全策略、来源验证、HTTPS、安全响应头和 `noindex`。
- 文件验证同时检查声明类型、实际文件签名、尺寸、大小和允许格式。
- 日志禁止记录密码、AI Key、作业正文、图片内容和完整 AI 响应。
- 安全事件只记录事件类型、账号标识、时间、结果和必要的非敏感诊断信息。

## GitHub 与发布流程

- GitHub `main` 是生产分支。
- Cloudflare Workers Builds 连接现有私有仓库。
- Pull Request 构建预览版本，不自动替换生产版本。
- 合并到 `main` 后自动构建并部署生产版本。
- 生产构建或部署失败时保留上一可用版本。
- Wrangler 配置只声明 Binding 名称和非敏感配置；资源 ID 和 Secrets 不写入源代码。
- 本地 `.dev.vars`、迁移凭据、数据库导出和用户文件继续由 `.gitignore` 排除。

## 数据迁移与切换

### 迁移前

1. 创建生产 D1、私有 R2 Bucket、任务 Queue 和死信 Queue。
2. 部署预览环境并使用合成测试数据验证全部功能。
3. 运行迁移工具的只读盘点模式，生成数据库记录和文件校验清单。
4. 创建带时间戳的本地只读备份。

### 最终迁移

1. 暂停本机服务写入。
2. 对 SQLite 执行一致性检查并导出最终数据。
3. 在本机交互式迁移三位教师的现有密码。
4. 将兼容 D1 的 SQL 和登录验证材料导入 D1。
5. 将 `.data/users/` 下的业务文件上传到 R2。
6. 对比用户、作业、图片、批注、任务和保存模板的记录数。
7. 对比每个迁移文件的字节数和 SHA-256。
8. 执行只读业务冒烟测试。
9. 使用专用测试账号和测试作业验证写入、AI、标注、PDF 和删除。
10. 发布正式 `*.workers.dev` 地址并停止本机生产服务。

迁移工具必须可重复运行。同一业务主键或对象键再次迁移时，应验证内容一致并跳过；内容冲突必须停止迁移，不能静默覆盖。

迁移失败时不切换生产入口。本机原始数据、时间戳备份和服务状态保持可恢复。

## 错误处理

- 网络中断时，浏览器对可安全重试的上传进行有限重试。
- 未完成的 R2 对象不创建正式业务记录，并由清理任务删除。
- AI 超时、上游错误和结构化响应错误使用不同内部错误码，对教师显示可操作的中文信息。
- Queue 消息有限重试；超过次数后进入死信队列并将任务标记为可人工重试。
- D1 成功但 R2 失败时执行补偿清理或保留可恢复状态。
- 浏览器图片或 PDF 处理失败时保留原始数据和上一成功版本。
- 免费额度错误、AI 任务额度错误、用户输入错误和系统故障不得混用同一个提示。

## 测试策略

实现采用测试驱动开发。每个新增行为先通过失败测试证明缺失，再编写最小实现使其通过。

### 单元与契约测试

- 保留现有领域、界面和安全测试。
- 为异步 Repository 接口和 D1 实现编写相同的业务契约测试。
- 为本地文件存储和 R2 File Store 编写相同的权限、完整性和删除契约测试。
- 测试 Queue 幂等、重试、死信和任务状态转换。
- 测试共享 AI Secret 不可通过设置接口读取或覆盖。
- 测试免费额度安全线及只读降级行为。

### 身份测试

- 正确账号密码
- 错误账号和错误密码的不可区分响应
- 一次性挑战过期与重复使用
- 登录失败锁定与恢复
- 会话撤销和修改密码
- 跨用户读取、修改、下载和删除
- 日志与错误响应的敏感信息检查

### 浏览器测试

- JPG、PNG、WebP、HEIC
- EXIF 方向纠正、压缩和大小限制
- 标注编辑与合成
- 单份 PDF 与批量 PDF
- 页面刷新后的任务恢复
- 免费额度提示和只读降级

### 迁移测试

- 使用生产数据库和文件的安全副本执行至少两次迁移演练。
- 验证迁移可重复运行且不会产生重复数据。
- 验证记录数、文件数、字节数和 SHA-256。
- 验证每位教师只能看到自己的迁移数据。

### 发布验证

正式迁移前运行：

```bash
npm test
npm run lint
npm run build
npm run test:e2e
```

同时运行 Cloudflare 本地 Binding 集成测试和预览环境冒烟测试。正式迁移后先执行只读冒烟测试，再使用专用测试账号验证写入和删除。

## 完成标准

只有同时满足以下条件才视为迁移完成：

- 免费 `*.workers.dev` 地址在用户电脑关机时仍可访问。
- 三位教师可使用原账号和原密码登录。
- 每位教师的历史数据、文件和数据隔离验证通过。
- 所有现有用户功能在云端可用。
- GitHub `main` 推送可自动发布，失败发布不影响上一版本。
- Cloudflare 托管未启用自动付费，应用安全线可阻止超额写入。
- AI Key 和登录密钥未进入 GitHub、D1 明文字段或日志。
- 本地只读备份已生成并验证可读。
- 全部自动化检查和迁移校验通过。
