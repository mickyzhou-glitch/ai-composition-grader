# 三份家长反馈设计

## 背景

当前 AI 分析会生成审题诊断、优点、需要修改、四维诊断和示范段落，但老师仍需手工整理一段适合发给家长的完整反馈。真实家长沟通通常不是要点列表，而是一段有称呼、有具体表扬、有问题定位和修改建议的连贯文本。

本功能在每次 AI 分析成功后生成 3 份完整反馈，供老师选择、修改和复制发送。三份反馈都以本次作文的真实内容为依据，不掌握历史作文时不得声称学生「相比上次」有所进步。

## 目标

- 每次新分析一次生成并保存 3 份完整的家长反馈。
- 3 份反馈分别采用「亲切详细」「专业清晰」「简短微信版」的表达方式，而不是简单复制或机械缩写。
- 在结果页顶部提供紧凑的标签切换界面，支持编辑、撤销当前未保存修改和一键复制。
- 反馈编辑沿用现有报告的复核、未保存提醒和保存机制。
- 旧报告没有家长反馈时仍可正常查看、编辑和导出原有内容。

## 非目标

- 不新增学生档案或跨作业历史对比能力。
- 不根据姓名猜测家长称谓或学生性别。
- 不在分析完成后发起第二次独立 AI 请求。
- 不为旧报告用前端模板临时拼接家长反馈。
- 不自动向微信、钉钉或其他外部渠道发送消息。
- 不把家长反馈加入现有 PDF 导出；本次范围只覆盖结果页复核与复制发送。

## 数据契约

新增家长反馈样式枚举：

```ts
type ParentFeedbackStyle = "warm" | "professional" | "concise";

interface ParentFeedback {
  style: ParentFeedbackStyle;
  title: string;
  content: string;
}
```

新生成报告的 `parentFeedbacks` 必须恰好包含 3 项，并按 `warm`、`professional`、`concise` 的固定顺序返回。每个样式只能出现一次，标题与正文均不能为空。

领域解析需要兼容没有 `parentFeedbacks` 的历史报告。历史数据归一化后使用空数组表示「未生成」，页面据此显示回退提示。AI 适配器对新分析执行更严格的校验：缺少任一版本、出现重复样式或正文为空时，均视为结构化响应不合格，不保存残缺报告。

报告仍作为一个整体保存到现有报告字段中，不新增数据库列或迁移脚本。老师编辑家长反馈后，通过现有报告保存接口和乐观并发版本一起持久化。

## AI 生成规则

AI 在同一次作文分析响应中生成 3 份反馈。每份都是可单独发送的完整文本，至少包含以下内容：

1. 合适的家长称呼和本次作文题目。
2. 基于原文的具体优点，例如选材、情节、细节、结构、语言或扣题表现。
3. 需要改进的具体位置或段落。
4. 可执行的修改方法，而不是笼统要求「写得更好」。

称呼规则：有学生姓名时使用「{学生姓名}家长」；没有姓名时使用「家长您好」。不推断「妈妈」「爸爸」或其他关系。

真实性规则：只引用当前作文、批注和报告中有依据的信息。当前数据流未提供历史作文，因此不得出现「相比上次」「这次进步很大」「延续了之前的优点」等跨作业判断，也不得虚构人物、情节、段落或老师未提供的观察。

三种版本的差异：

- `warm`：语气亲切自然，细节最完整，接近老师日常与家长沟通的表达。
- `professional`：结构清楚、判断直接，突出作文表现和修改动作。
- `concise`：适合即时通讯快速发送，篇幅更短，但仍保留具体优点、具体问题和修改建议。

3 份反馈必须在内容组织和措辞上形成真实差异，不能只替换少量同义词。AI 提示词继续要求只返回结构化 JSON，避免在字段外输出解释文字。

## 页面布局

家长反馈区域放在结果页标题、状态提示和数据保留提示之后，原有作文图片与报告工作区之前，占据页面可用的完整宽度。这一位置对应当前结果页顶部空白区域，并确保老师进入分析结果后首先看到可发给家长的内容。

区域采用已确认的「标签切换」布局：

- 标题为「给家长的反馈」，辅助文案说明已生成 3 份且可修改。
- 标签依次为「亲切详细」「专业清晰」「简短微信版」。
- 默认激活「亲切详细」，一次只展示并编辑一份反馈。
- 当前反馈正文使用多行文本框，随内容增长并保持清晰的段落换行。
- 操作区提供「恢复原文」和「复制反馈」。
- 移动端保持单列，标签可以等宽收缩或自然换行，不出现横向滚动和文本遮挡。

没有 `parentFeedbacks` 的旧报告显示一个紧凑的空状态：「暂无家长反馈，请重新分析作文后生成。」旧报告的其他区域保持原样。

## 交互与状态

编辑反馈时调用现有 `changeReport` 路径，使页面进入未保存状态。顶部已有的「保存复核」按钮负责保存全部报告修改；离开页面、强制刷新和重新分析时继续使用现有未保存保护。

组件在载入报告时保留 3 份反馈的已保存基线。「恢复原文」只恢复当前标签到最近一次载入或保存成功的版本，不影响另外两份反馈。保存成功后，新的已保存内容成为恢复基线。

「复制反馈」只复制当前标签正文，不附加标签标题或界面说明。复制成功后通过现有页面状态提示显示「家长反馈已复制」。复制失败时保留编辑内容，并提示老师选中文本手动复制。

分析任务进行期间，反馈文本框、标签内容修改和操作按钮均不可用，与原有报告编辑锁定规则一致。

## 组件边界

新增独立的 `ParentFeedbackEditor` 客户端组件，职责仅包括：

- 渲染 3 个标签及当前反馈文本框。
- 把正文修改通过回调交给 `ReviewPage`。
- 根据已保存基线恢复当前版本。
- 调用浏览器剪贴板并报告复制结果。
- 渲染历史报告的空状态。

`ReviewPage` 负责将组件放在全宽顶部位置、更新完整报告、维护未保存状态和展示全局提示。AI 适配器负责生成提示与新报告的严格校验。领域契约负责结构定义和历史数据归一化。数据库与 Worker API 继续传递完整报告，不增加专用接口。

## 错误处理

- AI 未返回恰好 3 份有效反馈时，沿用分析任务失败流程，不写入不完整报告。
- 复制 API 不可用或被浏览器拒绝时，显示可操作的手动复制提示，不清空正文。
- 保存发生版本冲突时，沿用现有冲突提示和强制刷新流程。
- 历史报告缺少字段时显示空状态，不抛出运行时错误，也不生成未经 AI 审核的替代文本。
- 标签状态异常时回退到第一份有效反馈；数据契约仍负责在持久化边界阻止重复样式和非法顺序。

## 测试策略

实现遵循测试驱动开发，每项行为先通过失败测试证明当前功能缺失，再编写最小实现。

### 领域与 AI 测试

- 新报告接受固定顺序且恰好 3 份的有效反馈。
- 新分析拒绝缺失版本、重复样式、空标题和空正文。
- 历史报告缺少字段时解析成功并归一化为空数组。
- AI 提示词包含称呼、具体优点、具体问题、修改方法和真实性约束。
- 未提供历史作文时，提示词明确禁止跨作业比较。

### 组件与页面测试

- 有反馈时显示 3 个标签，默认打开「亲切详细」。
- 切换标签后显示对应正文，且不会覆盖其他版本。
- 编辑正文后更新报告并进入未保存状态。
- 保存成功后新内容成为恢复基线。
- 「恢复原文」只还原当前标签。
- 「复制反馈」只复制当前正文，并分别覆盖成功与失败提示。
- 分析任务进行期间禁止编辑和复制。
- 旧报告显示空状态，原有报告编辑器仍可使用。
- 家长反馈区域位于原有作文图片与报告工作区之前。

### 回归验证

- 运行领域契约、AI 适配器、家长反馈组件和 `ReviewPage` 专项测试。
- 运行现有完整测试集，区分并记录与本功能无关的基线失败。
- 运行 TypeScript 检查和生产构建，确认 Next.js 静态导出与 Cloudflare Worker 构建仍成功。
- 在桌面和移动端浏览器检查长文本、标签、按钮和下方工作区不重叠。

## 成功标准

每次新的 AI 分析成功后，老师进入结果页即可在顶部看到 3 份内容真实、风格不同且可独立发送的家长反馈。老师能够切换、修改、恢复、保存并复制任一版本；没有历史作文时反馈不会声称「相比上次」进步；旧报告和现有批改、保存、导出流程不受影响。
