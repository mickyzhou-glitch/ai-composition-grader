# 已复核标记与一键导出设计

## 背景

批量审核通过后，服务端会持久化 `teacherReviewedAt`，并将作文从待审核队列中移除。
但批量审核页当前只把审核完成的作文保存在 React 内存状态中；用户离开页面后，作文既
不会再次出现在待审核队列，也没有稳定的导出清单入口。

## 目标

- 为已经完成教师复核、但尚未导出的作文显示独立的「已复核」标记。
- 继续将未完成教师复核的可审核作文显示为「待复核」。
- 用户离开并重新进入批量审核页后，仍能看到已复核但未导出的作文。
- 在历史页和批量审核页提供一键导出已复核作文的入口。
- 导出成功后沿用现有「已导出」状态，已导出的作文不再出现在已复核待导出清单。
- 不新增数据库字段，不改变现有教师复核接口、PDF 生成和导出预检契约。

## 状态定义

前端展示状态由现有服务端字段组合得出，不把「已复核」写入 `ReviewStatus` 枚举：

| 条件 | 展示状态 | 是否进入一键导出集合 |
| --- | --- | --- |
| `teacherReviewedAt` 有值且 `status !== "exported"` | 已复核 | 是 |
| `teacherReviewedAt` 为空且原状态为 `ready_for_review` | 待复核 | 否 |
| `status === "exported"` | 已导出 | 否 |
| 其他原有状态 | 沿用原状态文案 | 否 |

这样，重新分析、修改配置或替换图片清空 `teacherReviewedAt` 后，作文会自动回到待复核或
其他对应状态；导出成功后服务端将状态改为 `exported`，展示状态自然变为已导出。

## 方案比较

### 方案 A：复用历史接口，在前端组合展示状态（采用）

在 `app/lib/review-queue.ts` 增加纯函数，根据 `teacherReviewedAt` 和 `status` 判断已复核
待导出记录及展示状态。历史页和批量审核页都复用现有 `/api/reviews` 数据，不新增接口或
数据库查询。该方案与现有持久化字段一致，改动集中，并能同时覆盖刷新和重新进入页面。

### 方案 B：新增独立的已复核队列接口

新增服务端查询和路由，专门返回已复核待导出记录。状态边界更明确，但会重复现有历史查询、
增加本机与 D1 两套接口实现和测试，当前需求不需要额外的服务端能力，因此不采用。

### 方案 C：继续依赖批量审核页内存清单并写入浏览器缓存

可以减少接口读取，但浏览器缓存会产生过期、跨设备和多标签页不一致问题，不能作为持久化
导出资格，因此不采用。

## 页面行为

### 历史页

`StatusBadge` 接收由统一状态函数计算出的展示状态，并为「已复核」使用独立的样式类。
统计区增加「已复核」数量；「待复核」统计排除已经有 `teacherReviewedAt` 的记录。

历史批量操作区增加「一键导出已复核（N）」按钮。按钮只使用当前历史数据中满足已复核待
导出条件的作文 ID，不能把未审核、分析中或已导出的作文混入。按钮点击后复用现有
`downloadReviewPdfArchive`；成功后重新加载历史数据，使状态变为已导出，失败时保留记录并
显示错误。现有手动勾选导出和批量重新分析功能保持不变。

### 批量审核页

页面初始化并行读取待审核队列和 `/api/reviews` 历史列表。待审核队列继续只由服务端返回
未复核作文；历史列表则过滤出已复核待导出记录，作为可持久恢复的导出清单。

顶部清单入口改为「已复核待导出清单（N）」，数量来自服务端加载结果。清单页保留逐项勾选
导出，并增加针对全部已复核记录的一键导出按钮。批量审核成功后，当前返回的作文立即写入
清单；重新进入页面时以历史接口结果为准。导出成功后重新读取历史列表，已导出记录从清单
和数量中移除；导出失败时不提前移除记录。

清单中的「返回修改」继续打开单篇复核入口。若记录在其他页面被重新分析或发生版本变化，
现有服务端导出预检会拒绝导出并显示错误，页面保留该记录供用户刷新后处理。

## 数据流与错误处理

1. 页面从现有历史接口读取包含 `teacherReviewedAt` 和 `status` 的 `ReviewView`。
2. 共享纯函数将记录分为已复核待导出、已导出和其他状态。
3. 一键导出把筛选后的 ID 交给现有 PDF 批量下载函数。
4. 下载函数继续先读取最新详情并调用服务端 `export-check`，通过后生成 PDF/ZIP，再逐条标记
   为已导出。
5. 全部标记成功后页面重新读取历史数据；任何请求、版本或资格校验错误都显示现有错误文案，
   不在前端假设导出成功。

不修改服务端的 owner 隔离、审核资格、revision 校验和导出上限。服务端仍是最终导出资格
判断来源，前端筛选只负责展示和减少无效操作。

## 测试策略

### 纯函数与组件测试

- 已复核未导出、待复核、已导出和其他状态的判断互不混淆。
- 历史页显示「已复核」徽标、统计数量，并且一键导出只传递已复核未导出的 ID。
- 历史页一键导出成功后重新加载，记录显示为已导出；导出失败时记录仍在页面上。
- 批量审核页从历史接口恢复已复核清单，不依赖之前页面实例的内存状态。
- 批量审核页的一键导出只处理已复核记录，成功后重新加载并移除已导出记录。
- 空清单、请求失败和导出资格失败都保持可操作的错误或空状态。

### 浏览器验收

- 完成一篇批量审核后离开批量审核页，再重新进入，作文显示在「已复核待导出清单」。
- 历史页显示「已复核」标记和一键导出按钮，未复核作文不被按钮选中。
- 导出成功后同一条记录显示「已导出」，不再出现在已复核待导出清单。
- 桌面端和移动端状态徽标、按钮文字和清单布局不溢出、不遮挡操作区。

## 范围

本次调整只涉及前端状态展示、历史页与批量审核页的持久化清单恢复及相应测试。不修改
数据库 schema、服务端 API 路由、PDF 内容、导出资格规则或重新分析业务逻辑。
