# 示例作文段落数一致性设计

## 背景

自定义作文要求中可以明确写出五段结构，但内容模型提示词仍允许 `sampleParagraphs` 返回 1–10 段，服务端语义校验也只对内置题目强制五段。因此，模型返回三段时仍会被系统接受并保存。

本次修复让作业配置、模型提示词和服务端校验共享同一个段落数约束。

## 目标

- 自定义作文和内置作文默认都生成恰好 5 段示例正文。
- 历史作业配置不需要迁移，缺少新字段时自动按 5 段处理。
- 提示词要求的段落数与服务端实际校验的段落数始终一致。
- 保留未来配置 1–10 段的能力，但本次不新增可见的段落数表单控件。

## 方案比较

### 方案一：解析中文结构要求

从「第一段」「五段式」等文字推断段落数。该方案容易受表达方式影响，也会把自然语言解析规则散落到业务逻辑中，不采用。

### 方案二：所有作文硬编码为 5 段

提示词和校验都直接写死为 5。实现简单，但无法表达未来的其他段落结构，也容易再次出现多处常量不一致，不采用。

### 方案三：作业配置保存显式段落数，历史配置默认 5 段

在 `AssignmentConfig` 中新增可选的 `sampleParagraphCount`，取值范围为 1–10。提供单一辅助函数读取期望值；字段缺失时返回 5。提示词和语义校验都使用该函数。该方案兼顾历史数据兼容、当前修复和后续扩展，采用此方案。

## 数据与接口

`assignmentConfigSchema` 新增：

```ts
sampleParagraphCount: z.number().int().min(1).max(10).optional()
```

领域层导出：

```ts
expectedSampleParagraphCount(config: AssignmentConfig): number
```

该函数返回 `config.sampleParagraphCount ?? 5`。新建作业的内置配置和自定义配置都显式保存 `sampleParagraphCount: 5`。历史数据库中的 JSON 配置不需要迁移。

## 数据流

1. 新建作业页面提交包含 `sampleParagraphCount: 5` 的配置。
2. 作业配置 Schema 校验该值必须是 1–10 的整数。
3. 内容模型提示词通过领域辅助函数生成「必须恰好 N 段」规则。
4. 模型返回结果后，语义校验通过同一辅助函数检查数组长度。
5. 长度不符时返回现有 `sample_paragraphs` 验证错误，触发一次自动修复；修复后仍不符则报告 AI 返回无效。

## 兼容性

- 历史作业：字段缺失，按 5 段处理。
- 新作业：显式保存 5 段。
- 数据库：配置以 JSON 保存，无需表结构迁移。
- 报告基础 Schema：继续允许 1–10 段，具体作业的精确数量由语义校验负责。
- 旧的 OpenAI 兼容适配器：同步使用同一计数规则，避免不同分析链路行为不一致。

## 测试

- `AssignmentConfig` 接受 1–10 的整数，拒绝 0、11 和非整数。
- 缺少字段的历史配置期望值为 5，显式配置值按原值返回。
- 自定义作文缺少字段时，三段模型响应被拒绝并映射为 `sample_paragraphs`。
- 自定义作文返回五段时通过语义校验。
- 内容模型提示词明确要求恰好 5 段。
- 显式配置其他合法段落数时，提示词和语义校验采用该值。

## 非目标

- 不从 `structureRequirements` 自动推断段落数。
- 不在新建作业界面增加段落数输入控件。
- 不修改已经保存的三段报告；重新分析后会按新规则生成五段。
