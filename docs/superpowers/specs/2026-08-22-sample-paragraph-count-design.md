# 题目配置驱动的示范作文设计

## 背景

教师已经在题目下方填写适用年级、目标字数、写作要求和结构要求，但当前内容模型没有把这些配置全部作为硬约束：

- 自定义题目的提示词仍允许 `sampleParagraphs` 返回 1–10 段，服务端也不校验正文总字数，因此不足 600 字或段落数不符的范文仍会被保存。
- 提示词中硬编码了「六年级完整记叙文」等口径，容易弱化教师填写的「五升六」要求，使范文出现初中化、成人化的词汇、句式和感悟。
- 初次生成、自动修复、单段重写和全文重写使用的要求不完全一致，教师修改后可能再次失去原有年级、字数或格式约束。

本次修复让题目配置成为示范作文生成的唯一标准，并让提示词、自动修复和服务端校验共享同一组可确定检查的约束。

## 目标

- 教师填写的 `grade`、`targetCharacters`、`writingRequirements`、`structureRequirements` 和 `scoringFocus` 是生成与修改示范作文的唯一作业标准。
- `grade` 表示范文作者应呈现的学生水平。例如填写「五升六」时，范文应采用五年级毕业、即将升入六年级学生能够自然使用的词汇、句式、细节和思考深度，不写成初中生或成人范文。
- 示范正文的汉字数不得少于 `targetCharacters`，并允许最多上浮 10%；标题和修改建议不计入字数。例如目标为 600 字时，五段 `text` 合计必须为 600–660 个汉字。
- 自定义作文和内置作文默认都生成恰好 5 段示范正文，并严格遵循教师填写的结构要求。
- 历史作业配置不需要迁移，缺少新字段时自动按 5 段处理。
- 初次生成、自动修复、单段重写和全文重写使用相同的年级、字数和结构约束。
- 提示词要求的字数与段落数和服务端实际校验始终一致。
- 保留未来配置 1–10 段的能力，但本次不新增可见的段落数表单控件。

## 方案比较

### 方案一：只加强模型提示词

把教师配置重复写入提示词，生成后直接保存。改动最小，但模型仍可能少写或返回错误段落数，不能稳定解决问题，不采用。

### 方案二：增加独立的 AI 审稿请求

生成后再调用一次内容模型检查年级、字数和结构。该方案增加耗时与费用，而且第二个模型判断仍有随机性，不采用。

### 方案三：题目配置驱动提示词与确定性校验

提示词逐项声明教师配置的优先级和学生表达水平；服务端根据结构化的目标字数与段落数做确定性校验。首次响应不合格时沿用现有自动修复请求，修复后仍不合格则拒绝保存。该方案不增加正常生成的模型调用次数，并能稳定拦截过短或段落数错误的范文，采用此方案。

## 数据与接口

`assignmentConfigSchema` 新增：

```ts
sampleParagraphCount: z.number().int().min(1).max(10).optional()
```

领域层导出：

```ts
expectedSampleParagraphCount(config: AssignmentConfig): number
```

该函数返回 `config.sampleParagraphCount ?? 5`。新建作业的内置配置和自定义配置都显式保存 `sampleParagraphCount: 5`。历史数据库中的 JSON 配置不需要迁移。

领域层同时提供统一的正文长度规则：

```ts
sampleCharacterRange(config: AssignmentConfig): {
  minimum: number;
  maximum: number;
}
```

`minimum` 等于 `targetCharacters`，`maximum` 等于 `Math.ceil(targetCharacters * 1.1)`。字数只统计每段 `text` 中的汉字，不统计段落标题、标点和修改建议。

## 提示词规则

所有示范作文生成入口都必须完整携带当前 `AssignmentConfig`，并明确以下优先级：

1. 教师填写的作业配置高于内置的通用教学建议；通用建议不得覆盖或改写配置。
2. `grade` 是范文作者的学生水平，不只是批改老师的身份背景。模型在输出前须自查词汇、句式、修辞和感悟是否符合该水平。
3. `writingRequirements` 决定内容任务，`structureRequirements` 决定结构与格式，`scoringFocus` 决定重点；模型不得擅自套用另一种作文模板。
4. `targetCharacters` 通过动态范围写入提示词，不再固定写死为 600–700 字。
5. 「五升六」不得解释成初中作文水平。范文应保留小学生真实、自然的口吻，避免成人化议论、抽象说理、过密修辞和明显超出学生年龄的词语。

自动修复提示必须重复以上规则，并指出本次失败的实际字数或段落数，避免模型只修复 JSON 格式而忽略作文要求。

## 数据流

1. 新建作业页面保存教师填写的完整配置，并提交 `sampleParagraphCount: 5`。
2. 作业配置 Schema 校验段落数必须是 1–10 的整数，目标字数必须是正整数。
3. 内容模型提示词通过领域辅助函数生成动态年级、正文长度和段落格式规则。
4. 模型返回结果后，语义校验使用同一辅助函数检查段落数和所有 `text` 的汉字总数。
5. 字数或段落数不符时返回 `sample_paragraphs` 验证错误，触发一次自动修复；修复提示包含期望范围和实际结果。
6. 修复后仍不符合字数或段落数时，报告 AI 返回无效，不保存不合格范文。
7. 单段重写时，根据其余段落的现有汉字数计算该段允许的动态范围；全文重写时直接使用整篇范围。两者都在返回前校验。

年级表达水平属于语言质量要求，无法用简单词表可靠判断，因此不做武断的关键词拦截。系统通过明确提示、输出前自查和教师审核保证该要求；字数和段落数则由服务端硬校验。

## 兼容性

- 历史作业：字段缺失，按 5 段处理。
- 新作业：显式保存 5 段。
- 数据库：配置以 JSON 保存，无需表结构迁移。
- 报告基础 Schema：继续允许 1–10 段，具体作业的精确数量由语义校验负责。
- 现有目标字数继续从 `targetCharacters` 读取，无需新增数据库字段。
- 云端纯文本内容适配器与旧的 OpenAI 兼容适配器同步使用同一组规则，避免不同分析和重写链路行为不一致。

## 测试

- `AssignmentConfig` 接受 1–10 的整数，拒绝 0、11 和非整数。
- 缺少字段的历史配置期望值为 5，显式配置值按原值返回。
- 目标为 600 字时，正文范围为 600–660 个汉字；599 字和 661 字均被拒绝。
- 字数统计只包含各段 `text` 中的汉字，不包含标题、标点和修改建议。
- 自定义作文缺少段落数字段时，三段模型响应被拒绝并映射为 `sample_paragraphs`。
- 自定义作文返回符合字数范围的五段时通过语义校验。
- 内容模型的初次生成和修复提示明确包含教师填写的年级、写作要求、结构要求、评分重点、动态字数范围和段落数。
- 「五升六」提示明确要求小学生表达水平，并明确排除初中生或成人化表达。
- 自动修复提示包含实际字数与期望范围。
- 显式配置其他合法段落数时，提示词和语义校验采用该值。
- 单段重写后整篇不足或超过范围时拒绝结果；全文重写执行相同校验。
- 现有报告结构、家长反馈和批注校验测试保持通过。

## 非目标

- 不从 `structureRequirements` 的自然语言自动推断段落数；格式内容原样交给模型遵循，精确数量使用结构化的 `sampleParagraphCount`。
- 不在新建作业界面增加段落数输入控件。
- 不修改已经保存的三段报告；重新分析后会按新规则生成五段。
- 不使用固定词表判断学生年龄水平，避免误伤合理表达。
