# 详情页直接导出 PDF 设计

## 背景

作文详情页已经提供完整的批改复核能力，但当前 PDF 下载函数会校验
`teacherReviewedAt`。该时间只在批量审核页通过教师复核接口写入，因此老师即使已在
详情页核对内容，仍会被要求回到批量审核页再次审核。

## 目标

- 在作文详情页点击「导出 PDF」后，一次完成当前内容保存、教师复核确认和 PDF 下载。
- 未保存的学生姓名、批改报告和图片批注必须进入本次导出的 PDF。
- 已复核且没有本地修改的记录直接下载，避免无意义地重复保存。
- 批量审核页和批量导出的审核资格限制保持不变。

## 方案比较

### 方案 A：详情页导出前按需完成教师复核（采用）

当记录尚未教师复核或页面存在未保存修改时，详情页先调用现有
`POST /api/reviews/:id/teacher-review` 接口，原子保存当前内容并写入复核时间；成功后再调用
现有 PDF 下载函数。该方案复用现有并发版本保护和服务端校验，同时保留批量导出规则。

### 方案 B：移除所有 PDF 导出的教师复核校验

改动最少，但会同时放宽批量导出和服务端 PDF 导出，破坏「批量清单只包含已审核作文」
的既有约束，因此不采用。

### 方案 C：让「保存复核」统一写入教师复核时间

语义上可行，但没有本地修改时按钮当前不可用，仍不能满足一次点击导出；同时会改变普通
保存动作的全局含义，因此不采用。

## 交互与数据流

1. 用户点击详情页「导出 PDF」。
2. 前端验证当前报告；无效时显示现有字段级错误，不发出保存或下载请求。
3. 若记录未复核或页面有未保存修改，前端以当前 `revision`、学生姓名、报告和批注调用教师
   复核接口。
4. 教师复核成功后，用接口返回值更新页面状态并清除 `dirty` 标记。
5. 调用现有 `downloadReviewPdf`。该函数重新读取已复核的最新版本，通过现有导出校验，
   生成文件、触发下载并标记为已导出。
6. 刷新详情数据并显示「PDF 已导出并开始下载。」。

已经复核且没有本地修改时跳过第 3、4 步，直接执行下载。

## 错误处理

- 报告校验失败：沿用详情页现有的精确校验文案。
- 版本冲突：提示「内容发生冲突，请刷新后重新检查。」，不生成 PDF。
- 教师复核保存失败：保留页面当前编辑和 `dirty` 状态，不生成 PDF。
- PDF 生成或下载失败：展示现有导出错误；若教师复核已经成功，页面保持已保存状态，用户可
  直接重试导出。
- 整个流程沿用导出按钮的忙碌状态，阻止保存、分析、替换和重复导出并发执行。

## 测试

- 组件测试：未复核且无修改时，导出先提交当前内容到教师复核接口，再下载 PDF。
- 组件测试：存在未保存修改时，导出按钮可用，提交修改后的内容，随后下载最新版本 PDF。
- 组件测试：已复核且无修改时跳过教师复核请求，直接下载。
- 组件测试：报告无效或教师复核失败时不调用 PDF 下载，并保留当前修改。
- 回归测试：批量导出的资格校验测试继续通过。

## 范围

本次只调整详情页导出编排及其测试。不修改 PDF 排版、批量审核交互、批量导出资格规则、
数据库结构或 API 契约。
