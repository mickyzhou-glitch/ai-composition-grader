# 示范作文字数容错设计

## 背景

`teacher01` 有 36 篇待复核作文需要按最新批改能力重新分析。线上任务全部使用目标 600 字、5 段的题目配置。首轮入队后，已消费的 24 篇全部失败，其中 20 篇为 `AI_INVALID_RESPONSE_sample_paragraphs`，另外 4 篇为整份报告修复后的 Schema 错误。剩余 12 篇已暂停在 Cloudflare Queue 中。

现有校验要求示范作文各段 `text` 的汉字总数必须为 600–660。内容模型已能返回完整报告，但对精确总字数的遵循不稳定；当系统要求重写整份 JSON 时，还可能损坏原本正确的字段。

## 决策

将示范作文的可接受汉字总数调整为：

- 下限：`targetCharacters - 50`，最低为 1。
- 上限：`targetCharacters + 100`。

因此，当题目目标为 600 字时，服务端接受 550–700 个汉字。模型提示词、生成结果校验、单段重写和全文重写继续共用同一个 `resolveSampleWritingRequirements` 结果，避免不同入口使用不同阈值。

## 保持严格的规则

- `sampleParagraphs` 必须恰好符合题目配置的段落数；当前线上数据仍为 5 段。
- 每段的 `title`、`text` 和 `suggestion` 必须是非空字符串。
- JSON Schema、题目结构覆盖、家长反馈、等级和批注页码等现有校验不变。
- 不通过截断、拼接填充词或修改数据库报告来伪造合格结果。

## 实现范围

只修改域层的示范作文字数解析规则及相关测试。现有 AI 适配器已统一调用该规则，不需要新增第三次模型请求、修改数据库 Schema 或改动前端。

## 线上恢复

1. 编写回归测试，先确认 549 和 701 个汉字被拒绝，550 和 700 个汉字被接受。
2. 修改共享字数规则，运行 AI 适配器测试、全量单元测试、Lint 和生产构建。
3. 部署 Cloudflare Worker，确认线上配置已生效。
4. 恢复队列中尚未消费的 12 篇。
5. 对已失败的 24 篇重新提交 `content_only` 任务，复用现有 OCR。
6. 持续核对 36 篇的成功、运行中和失败数；失败项仅针对原因重试，不重复处理已成功项。

## 验收标准

- 目标 600 字时，提示词和服务端校验统一为 550–700 个汉字。
- 5 段要求和所有其他核心校验保持不变。
- 36 篇作文都产生新的待复核报告，每篇对应的最新分析任务为 `succeeded`。
- 临时操作会话在任务提交后立即撤销。

## 回滚

如果新版部署后出现新的系统性错误，再次暂停分析队列，将 Worker 回滚到部署前版本，保留已完成的报告，只重试未成功任务。
