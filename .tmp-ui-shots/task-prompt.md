# 任务：AI作文批改助手 — 待审批原话 + 退回弹窗可选已通过规则 + 修第二个输入框

工作目录就是本仓库。截图在 `.tmp-ui-shots/`：
- `return-modal.jpg`：退回后台修改弹窗（结构问题 / 内容建议两个大文本框）
- `messy-overlay.jpg`：用户说「是乱的，想填第二个也填不了了」时的界面（叠层/遮挡）
- `pending-rules.jpg`：长期批改规则「待审批」列表现在显示「归纳后的规则」

## 需求（按优先级）

### A. 待审批：不要 AI 归纳文，直接给老师原话审核
现状：待审批卡片展示「归纳后的规则」，来源意见被压成归纳结果，用户明确说「归纳的不好，直接把我的原话给我审核」。
目标：
- 待审批列表/卡片**主文案就是老师写下的原话**（修改意见 / 退回意见原文），不要再生成或展示另一套「归纳后的规则」作为主内容。
- 通过后，长期规则内容应写入**该原话**（或原话列表），不是 AI 改写版。
- 若当前流水线有「AI 从意见归纳成候选规则」步骤：停用或跳过改写；候选记录直接存原话。可保留轻量去重（完全相同原文合并），但文案不得改写。
- UI 文案相应改掉（例如不要再写「由 AI 从…归纳而来」为主说明，可改为「来自你的修改/退回意见，通过后写入该题目的长期规则」）。
- 小红点/待审批数量逻辑保持。

### B. 退回弹窗：已通过的长期规则做成可选项，可选也可直接编辑
对应 `return-modal.jpg` 里「结构问题 / 共性问题 (仅同名作文)」输入区（以及若适用的内容建议区——内容建议是仅当前文章，一般不套长期规则；长期规则只对同名题目生效）。
目标：
- 加载该题目**已审批通过**的长期规则，展示为可点击选项（chips / 列表均可）。
- 点击后把规则原文填入对应文本框；填入后仍可自由编辑。
- 也可不选、直接手打。
- 可多选：多个规则文本合理拼接（换行分隔），不要覆盖用户已手改且未关联的内容时要小心——合理做法：点击追加到文本框末尾，或选中态切换；优先「点选填入/追加，框内可改」。

### C. 修「第二个框填不了 / 乱」
对照 `messy-overlay.jpg` 与退回弹窗交互：用户无法正常填写第二个输入框，布局叠层混乱。
请自行排查：z-index、pointer-events、fixed/absolute 遮罩、弹层高度、父级 overflow、审核页批注层盖住弹窗输入等。修好后两个文本框都能正常聚焦输入。

## 约束
- 长期批改规则**只对同名题目生效**，不跨题目。
- **不要部署上线**；改本地代码即可。用户未说「上线」。
- 尽量补/改相关单测或组件测试；跑得动的测试跑一下。
- 中文 UI 文案简洁。
- 不要无关大重构。

## 完成标准
1. 待审批主展示 = 原话；通过后长期规则 = 原话。
2. 退回弹窗能看到该题已通过规则选项，点选可填入并可继续编辑。
3. 两个输入框都能正常输入，无明显叠层挡点击。
4. 简要说明改了哪些文件、如何验证。
